# 1. 目的

# 3. 処理詳細

## 3.1. 予定の自動適用 (`apply_scheduled_status`)

社員が事前登録した `ScheduledStatus` を当日の出社状態として自動適用する処理。

- **想定実行環境**: Linuxの `cron`（毎分実行）等から管理コマンドを呼び出す構成。
- **トリガー**: 毎分定期実行（および画面からの当日予定登録時の即時適用）。
- **対象データ**: `target_date` が実行日と一致し、`deleted_at IS NULL` かつ `applied_at IS NULL` である `ScheduledStatus` レコード。
- **処理内容**:
  1. システム管理者権限（`is_superuser=True`）のユーザーを取得する（更新者記録用）。
  2. 開始時刻判定:
     - `start_time` が設定されている場合: 現在時刻が `start_time` に達している場合のみ適用（未達の場合は次回実行までスキップ）。
     - `start_time` が未設定の場合: 当日予定としてそのまま適用。
  3. 各レコードに対し、対応する `Employee` の `Presence` レコードを作成または更新する。
  4. `status`、`destination` をコピーし、`end_time` がある場合は実行日の日付と結合して `end_datetime` にセットする。
  5. `PresenceHistory` に履歴レコードを作成し、SSE（Server-Sent Events）で更新イベントをブロードキャストする。
  6. 対象の `ScheduledStatus.applied_at` に適用日時を記録し、手動ステータス変更後の再上書きを防止する。

---

# 4. エラーハンドリング

バッチ処理中のエラーは標準出力およびエラーログに出力される。
トランザクション制御(`transaction.atomic()`)により、処理全体または1件ごとにロールバックが行われる。
